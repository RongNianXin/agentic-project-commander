# Codex 历史任务批量迁移包

## 当前状态

- 阶段 A 已完成，仅构建和模拟，没有修改真实会话。
- `stage-a-report.json` 是完整机器可读报告。
- 阶段 B 尚未执行。

## 迁移目的

仅扫描 Codex 当前未归档的任务，移除其中与原提供商绑定、切换账号或 API 提供商后无法验证的隐藏推理和压缩密文，同时保留用户消息、AI 可见答复、工具调用及其他非加密结构。`archived_sessions` 中的已归档任务不会被扫描、备份或修改。它解决的是“继续同一个可见任务”的兼容问题，不会也不能把原提供商的隐藏推理密文转换给另一个提供商。

## 阶段 A 结果

原始机器报告包含本地任务标识和统计数据，不随公开包分发。公开验证结论是：模拟流程完成、失败保护生效、加密字段按预期移除、非加密结构摘要保持一致，手工备份不会被识别为正式任务。

## 阶段 B 安装步骤

1. 完全退出 Codex，确认任务栏和系统托盘中也没有 Codex。
2. 完全退出 CC-Switch，确认系统托盘中也没有 CC-Switch。
3. 双击 `安装批量迁移.cmd`。
4. 等待窗口显示“安装成功”和备份目录后，再启动 Codex。
5. 先打开原报错任务并发送一条短消息，再切换另一个提供商复测同一任务。

安装器若检测到 Codex、ChatGPT、CC-Switch 或相关 Codex 后台进程，必定拒绝执行。它只枚举 `.codex\sessions` 中当前未归档的任务，不再进入 `.codex\archived_sessions`。随后生成并校验候选文件，再备份受影响的未归档任务、Codex 配置/状态数据库和 CC-Switch 数据库，最后逐文件原子替换。任何可检测失败都会自动恢复已提交文件。

提交前可运行 `node safety_tests.mjs` 和 `node install_bulk_codex_migration.mjs --self-test`。前者验证可见消息、附件元数据和未知加密结构的失败保护；后者只枚举并校验未归档任务路径，不读取或修改任务内容。

## 回滚

Codex 与 CC-Switch 完全退出后，双击 `回滚最近一次批量迁移.cmd`。回滚前，工具还会先备份迁移后的现场，避免覆盖后无法取证。

## 备份位置

`<USER_HOME>\Documents\Codex\CodexSessionBackups\bulk-<TIMESTAMP>`

每次安装目录内包含 `manifest.json`、原始任务文件副本，以及当时存在的 Codex/CC-Switch 配置和数据库副本。恢复时应使用回滚脚本，不应只覆盖 `config.toml`；单独还原配置不会还原任务历史，也可能制造配置与历史状态不一致。

## 已知边界

这次批量迁移只处理运行时已经存在于未归档任务中的密文。已归档任务保持原样；以后将它们恢复到当前列表后，如需跨账号续接，应再次运行脚本。某个提供商继续写入新的隐藏密文，再切换到不能解密它的提供商，仍可能复发。要实现长期自动兼容，需要在 CC-Switch 的切换流程中加入同一套“离线清理 + 备份 + 校验”机制，或由上游正式支持跨提供商状态转换；仅靠 `model_provider = "custom"` 不能改变密文归属。
