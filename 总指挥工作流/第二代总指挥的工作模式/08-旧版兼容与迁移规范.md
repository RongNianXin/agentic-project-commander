# 旧版兼容与迁移规范

本文件只服务从旧版、自建或其他总指挥工作流迁移的使用者。公开仓库没有发布一套需要新用户先学习的完整“第一代”规则；第一次使用本仓库时直接跳过本文件，从 `01-操作者操作手册.md` 开始。

## 1. 适用门禁

只有当前项目已经存在另一套任务 ID、状态索引、事件账本、交接记录或自动化时，才加载本文件。仅仅看到历史名称、旧聊天或旧目录，不构成迁移任务。

旧版位置只能从使用者提供的路径、项目入口或已登记索引中只读定位；候选不唯一时请求一次确认，不扫描整块磁盘，也不把旧版目录加入日常必读清单。

## 2. 不继承的状态

迁移时不得直接继承旧版的：

- 总指挥或专项任务 ID、队列和事件游标；
- 运行中进程、远端授权、完成声明和人工/专业结论；
- 中央状态、交接记录、自动化配置和受管生成块；
- 无法证明仍有效的责任归属、Base/Head、检查结果或恢复断点。

可以复用经过当前事实核验的安全边界、术语和设计经验；复用后写入当前工作流自己的状态或规则版本，不让两套系统共享同一事实源。

## 3. 迁移步骤

1. 建立只读映射，列出旧目标、任务、状态、文件和自动化。
2. 以当前代码、Git/平台、项目规则和可回读证据核验仍有效事实。
3. 对重复、冲突和失效记录分类，只生成当前工作流需要的最小状态。
4. 影子比较旧/新断点；影响范围不可靠时停止并请求最小确认。
5. 经使用者明确确认后，原子切换唯一总指挥和中央写入者。
6. 旧记录保留为只读历史，不删除、不覆盖、不整体搬迁。

## 4. 防止架构回退

迁移不能恢复默认事件 FIFO、Heartbeat、标题同步、多份同义中央视图，不能要求使用者在两个窗口重复描述或转发结果，也不能强制把普通实现全部下发。是否创建例外专项任务统一按 `02-总指挥核心规则.md` 的净收益门禁判断；通用防膨胀检查统一由 `06-复盘与优化规则.md` 维护。

## 5. 污染判定

出现以下任一情况，暂停受影响动作并报告：

- 无法判断某条任务、状态或授权属于哪套工作流；
- 两个总指挥同时派发任务或写中央状态；
- 当前任务写入旧版状态文件，或旧提示词覆盖当前规则；
- 旧授权、运行状态或完成声明未经回源便被当作当前事实；
- 为维持迁移兼容而重新建立高频同步或重复上下文。
