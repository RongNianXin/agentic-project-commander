# 总指挥交接记录模板

本模板属于抽象层，所有字段由旧总指挥自动读取或生成，不是人工表单。真正使用时，在具体项目管理目录生成实例记录；持久化与逻辑 ID 按索引规范执行，不把项目实例数据写回本目录。便携实例只保留聚合事实和证据指针，轻量加载与展开条件以 `总指挥轻量交接启动配置.md` 为准。

## 新总指挥第一次只读动作

操作者可直接使用 `01-操作者操作手册.md` 的“场景 6A：新总指挥接收正常交接”启动本节。模板只保存项目事实和第一次只读动作，不在此复制操作者提示词，以免两处规则漂移。

1. 完整读取 `总指挥轻量交接启动配置.md`，建立本任务加载记录并比对配置及来源规则指纹；异常项按配置展开。
2. 按“快照 → 项目入口 → 当前进度视图当前区 → AI 状态索引当前指针 → 唯一活跃任务当前阶段”的最小链读取。
3. 用聚合计数、Head、指纹和 PASS/WARN/FAIL 核对当前 Git/GitHub 基线、单写者和任务断点；只有异常项才展开。
4. 只刷新截点后变化、未闭环、派生交付物和交接记录中标记为“受影响/待确认”的对象。人工核验优先读取当前轮次清单和上一轮结案摘要；上一关闭轮次原图默认不读取。
5. 若快照或游标不可靠，先扩大受影响部分核账；仍无法恢复时才退回全量。候选阶段不启动任何推进。
6. 候选报告可切换后等待操作者停止或归档旧总指挥并发送最终确认；再做最小失效复核，通过后按索引规范更新当前总指挥、交接记录和可靠截点并回读。授权有效性按新任务重新核验。

旧任务不可读或不可写时，不要求旧总指挥完成主动交接。新总指挥改按“入口 → 灾难恢复热快照 → 状态索引 → 当前 Git/平台事实 → 受影响冷证据”恢复；先核对已完成凭证和执行中断点，禁止从第一步重跑整个队列。恢复可靠后写入新控制面世代；事实或修改归属仍冲突时保持只读并列出最小缺口。

## 例外专项或临时 AI 协作返回包

通过净收益门禁的例外专项或临时 AI 未取得总指挥调度权时不得直接修改中央状态；可以更新便携快照副本。结束时直接向总指挥返回：更新后的快照、实际完成、代码/远端变化及回执、验证、未完成项、阻断、下一责任人、快照是否失效，以及建议写回的最小状态增量；不要求使用者人工转发。视觉观察任务是更窄的临时角色：只返回本轮视觉结果卡和证据定位，不返回整批图片或接管建议，也不把观察到的表象直接升级为代码根因或专业结论。

## 不应从交接记录直接推断的内容

- 当前 GitHub 状态；
- 当前模型或 Codex 窗口真实配置；
- 任务是否仍在运行；
- 领域专家或队友是否已经收到消息；
- 任何远端写操作是否已经完成。
- 本轮使用者本人、本轮协作成员和目标是否仍与上一轮相同；必须以当前指令为准。
- 旧授权是否仍有效；新目标或新轮次不得从交接记录静默继承权限。
