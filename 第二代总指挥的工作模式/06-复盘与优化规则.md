# 复盘与优化规则

## 1. 复盘目的

复盘不是重新规划项目，也不是增加新的管理文档；它只回答一个问题：

> 最近一批任务中，哪些流程可以在不降低执行质量和安全性的前提下变得更短、更准、更自动化？

## 2. 建议的三视角审查

使用者本人、本轮协作成员和其他 AI 的建议均作为候选方案处理。总指挥从工程、程序实现和 AI 执行三个视角做一次合并审查，区分事实、推断、偏好和待确认事项。审查深度与影响相称：简单建议静默检查，不建立三个重复任务或输出三份报告；只有发现会影响结论、范围、风险或执行的问题时才说明。没有证据支持的问题不得为了“对抗式”形式而虚构。

工作流规则的新增、删除或修改默认执行完整闭环：

1. 拟定最小修改方案，明确唯一主维护文档、需要保留的安全摘要和验收方式；
2. 修改前对抗式审查目标、团队规范、权限、安全、可执行性、Token、耦合和规则冲突；
3. 根据审查结果修正方案，不把未解决的阻断问题带入文档；
4. 正式修改规则，并记录版本与实际改动；
5. 修改后对抗式复检跨文档一致性、旧规则残留、是否扩大授权、是否误伤正常流程、复杂度和验证结果；发现阻断问题时继续修正后再复检。

使用者本人简述“修改规则”“修改后对抗式审查”等同于授权完成上述低风险本地闭环，不要求其逐步重复确认。若不同修改方向会显著改变目标、远端/生产/不可逆权限、安全边界或团队硬规则，必须在正式修改前暂停并请求决定。简单措辞修正可以静默完成前四步，但不得跳过修改后的最小一致性检查；不得先把有争议的方案落地，再用事后审查为既成事实背书。

## 3. 触发时机

- 一个 Goal 完成或暂停后；
- 集中接管一批 Issue/PR 收口后；
- 连续出现两次以上重复读取、重复任务或无效重试；
- 目标发生重大变化后；
- 交接前；
- 使用者本人主动要求复盘时。

不需要每轮微小操作都复盘。

## 4. 复盘证据

只使用实际可回读的内容：

- 工具调用轮次和失败重试；
- 读取的文档和重复读取次数；
- 任务卡数量、并行波次和等待时间；
- 主窗口与例外专项任务合计的规则载入、证据重复、派发、回执、再汇总和人工转发成本；
- 测试、截图、日志和回执；
- 重型命令、浏览器 worker 数、前台窗口、GPU stall、超时、残留服务和进程归属；
- 人工确认次数；
- 被暂停、取消或替代的任务；
- 发生的状态漂移和重新扫描原因；
- `AI状态索引.md` 中的轮次、任务、授权卡、截点和失败记录。

没有数据时标记“待确认”，不要凭感觉给出精确节省比例。

## 5. 检查清单

1. **范围与事实**：是否错误把非 GitHub 平台套入本流程；身份是否只以 GitHub 账号为主键；母任务、决策版本、已确认/否决/未决项、候选/执行/依赖/排除是否可核账；“请执行”是否覆盖完整母任务而非最后一个细节；建议、历史和索引是否回源验证；多目标和多成员是否被错误做成笛卡尔积；是否因成员列名、历史参与或同标签误纳入无关任务；是否漏掉已列成员创建且内容命中目标的对象；每个正式候选是否有命中目标、触发成员和正向纳入依据；跨模块强信号是否进入正式候选、弱关联是否单独登记并默认排除、无关活动是否被误报为弱关联；普通整卡确认是否错误带入弱关联观察项；3A/3B 是否遗漏使用者本人创建且命中目标对象上的协作成员实质活动，或误把目标外普通活动当成强信号；增量是否覆盖变化、旧欠账和派生对象；启动与结束是否复用同一组扫描入口；2A 兼容性扫描是否被误当成完整 3A 执行。
2. **调度与资源**：长任务是否按偏航风险使用平台可见分步计划，简单边界任务是否被过度计划；普通实现是否默认留在总指挥主窗口；每个例外专项任务是否有独立边界和可核验的总 Token/关键路径净收益，还是机械采用“所有代码必须下发”的硬分工；同一根因、PR、worktree、冲突域或连续 UI 反馈是否被错误拆窗；同一对象是否只有一个规范记录和责任窗口；依赖、冲突、阻断、堆叠 PR 和资源门禁是否正确，单项失败是否错误暂停全局；是否错误承诺 CPU/内存百分比或用高频监控增加负担；构建、完整测试、依赖安装、模型、媒体、浏览器和 GPU/WebGL 是否被叠加运行；Playwright 本地回归是否默认无头单 worker；已知可见窗口是否在卡内预告、运行中临时需要时是否作为非阻断通知直接继续而没有无价值等待、窗口是否限制为单一上下文并及时关闭；是否错误借可见窗口绕过设备、账号、隐私或远端动作的独立门禁；开发服务和测试 runner 是否在无用途后残留；“后台”是否被误当作低资源；发生卡顿、GPU stall、大面积无关超时或 trace 损坏时，是否停止新增重型步骤、保存断点并降为最小范围串行验证；是否只看直接父项而漏掉已知父链中的首个不稳定节点；PR 树是否只表达直接 Base/Head，Issue 树是否只表达有证据的父项、前置或阻断，是否把 Related 误画为依赖或把树顺序误当合并授权。
高资源门禁复盘还必须确认：计划是否提前识别了该步骤；若执行中才发现，是否在启动前暂停并生成了补充授权卡；阶段结束回执是否同时给出待授权状态、精确命令、范围、耗时、风险、准备事项、终止方式和可复制确认文本，而不是只写“之后执行”。

3. **工程质量**：方案是否满足验收且保持简单；是否机械套用 DRY/SRP/KISS/YAGNI，遗漏契约、兼容、错误处理、测试，或无证据增加扩展性和可观测性；偶发视觉、交互、几何或算法故障是否在修改前冻结素材、模式、参数、种子偏移、浏览器状态、代码基线和通过/失败标准，是否把刷新后前置条件未恢复的无效运行或单次成功误当成根因和稳定修复证据。
4. **授权与安全**：系统与团队硬禁止项是否优先；仓库具体流程是否正确覆盖通用工作流偏好；低风险缺口是否只形成局部门禁；两阶段确认是否有效；组合卡是否按场景分区授权；卡外动作、Auto-review、Assignee、Reviewer 和远端写入是否越权；历史授权或其他场景授权是否被静默继承。
5. **远端协作**：本地与远端是否分开记录；PR 在 Push、转 Ready 或请求 Reviewer 前，是否已完成作者侧自修闭环，先处理所有范围内、可复现、根因明确且不涉及他人责任或专业决策的问题；剩余问题是否逐项写明证据、责任、阻断程度和恢复条件；是否错误通过删除测试、降低断言、空提交或无意义 Push 清除失败；Review 类型、Cross-reference、汇总回链、Draft PR 交棒、临时推进和责任归属是否有真实证据且不制造噪声；是否错误用时间线最后一条事件的作者判断轮到谁，是否存在无主语交棒、未送达却写成待对方或双方互等；Review 是否绑定当前 Head，checks 为零时是否继续查询 Actions；是否为刷新时间线制造无价值 Comment。
   远端交付效率另核对：制卡时是否区分协作元数据型、代码交付型和高资源交付型并给出有依据的估计区间；首次 Push 前是否从当前 workflow、脚本和受影响文件形成并通过 CI 等价本地门禁；是否把同步、冲突、架构门禁和本地可复现失败合并在同一 Push 波次；远端新增证据是否才触发下一波次；CI等待期是否并行了不依赖结果的只读核账，又避免了提前远端表态、修改同一Head或争用高资源；是否记录实际关键路径、Push/CI波次数和可避免等待。
6. **状态与索引**：规则版本、规则根目录、逐文件指纹、本任务加载记录、任务/卡片 ID、截点、分支和回执是否自动记录；是否错误跨任务继承“已读”，或把同名、附件重复出现、Prompt Cache 命中当成文件相同的证据；主场景、队列分区、规范记录和跨场景引用是否唯一可回源；当前行动方、送达回执、完成凭证、恢复条件、后续行动方、Review 绑定 Head 与有效性是否可回源；发生实质判断的对象是否保存可迁移决策回执，避免“为什么这样做”只存在聊天中；索引是否轻量且未混入其他项目或旧版状态；身份和目标是否来自本轮输入；长任务是否在开始前、恢复意义变化和每批结束后低频更新灾难恢复热快照；是否错误等到整组任务完成才落盘、按消息高频写入、把聊天/日志/Diff复制进热状态、让专项 AI 覆盖中央状态，或从旧快照继承远端授权。
   稳定截点记账另核对：是否只在授权、首次远端写前、Head/授权/恢复路径变化和独立批次完成时原子更新中央记录；是否把命令级进度重复写进入口、热视图、索引和冷记录；CI完成后是否一次性回填关键路径与波次数据。
7. **效率与复杂度**：是否以整个工作流而非单个总指挥窗口计算 Token；是否重复读取或重复上传未变化的规则、历史、附件、图片或日志；新任务是否至少完整读取本轮适用规则一次，同一任务是否在指纹未变且加载记录可靠时复用读取结果；专项任务是否重读主窗口已经掌握的同一代码、规则、Issue/PR 和人工反馈，是否把派发、等待、回执和再汇总漏出成本统计；是否要求使用者双窗口重复描述或转发结果；跨场景扫描是否先读候选元数据、再按相交和风险深读；增量结束核账是否内置复用本轮数据，还是错误地另建每日步骤、重复全量扫描或深读未变化对象；附件是否正确分为必要、辅助和重复；首次高成本材料分析后是否保存轻量证据摘要；图片密集人工核验是否有唯一轮次清单、关闭后 `default_read=false`、下一轮默认不展开上一轮原图，是否错误删除索引或把“禁止回读”误报为“已删除”；形成可靠断点后是否只在净收益明确时换窗，还是一阶段一窗口或继续让无关旧图片占据新轮次；缓存命中率是否与普通输入、缓存绝对量、输出、延迟、失败和费用分开解释；窗口路由是否由 AI 依据稳定截点、未完成工作和决策回执判断，是否错误使用固定轮数/Token 阈值、一问一窗口或无回执分流；是否存在过碎任务、过高模型、重复汇报、无效重试、过多必读文档或可被稳定模板/工具替代的步骤；偶发故障是否先集中采证和定位根因、再分层回归，是否在无实质变化时重复完整套件，或反过来以节省 Token/时间为由跳过高风险真实素材、相邻输入稳定性和最终交付门禁。
8. **收口与人话回执**：是否把计划误报为完成；2A 与 3A 是否独立核账且无关 3A 未拖住 2A；Issue 草案键、正式编号、实现、PR 和 Reviewer 门禁是否可映射；没有真实交付时是否错误创建空 PR；预期动作、实际动作、回执和四类差集是否闭环；场景 2A/3A/3B 是否输出两棵树；查看顺序、当前行动方、交棒和阻断是否清楚；是否自动区分必须/建议人工操作，建议项是否错误阻断主流程；使用者本人的操作包是否缺少类型、阻断性、不执行影响、推荐方案、步骤、预期结果、异常反馈或下一步提示词；是否把其他成员的动作错误混入操作包，或未经授权、无协作价值地生成远端 Comment。

图片密集轮次另做一次压缩前隔离核对：是否先比较继续主窗口与视觉观察任务的总成本；是否只有隔离净收益明确时才开任务；是否做到一个大轮次最多一个观察任务而非一图一任务；观察任务是否只读当前轮、只有指定结果卡写权且没有代码/中央状态/远端权限；总指挥是否只摄入结构化结果卡并按触发条件最小回图；是否为省 Token 统一降清晰度而损害细线、文字、颜色或几何证据；是否把“视觉成本被隔离”误报为“视觉成本已消失”。

长寿命总指挥任务另做一次会话健康核对：是否在规定时点按 `05-模型选择与资源策略.md` 记录本地会话文件路径、大小、检查时间和软门禁；是否把多轮自动压缩正确视为正常续行，而不是异常或直接交接条件；是否错误使用自动压缩次数、压缩前峰值、固定上下文占比或本地文件大小推断 Token 费用；达到 `200 MiB` 是否执行交接评估，达到 `300 MiB` 是否停止启动新大型波次并在当前原子步骤收口、稳定截点形成后优先交接；是否错误强行中断结果未知的工具或远端动作。

### 高 Token 架构防复发红线

以下任一现象出现即视为流程回归，必须优先简化，而不是继续在其上增加补丁：

1. 总指挥被再次禁止普通实现，导致所有代码、测试、Commit 或远端授权动作都必须经过专项窗口。
2. 默认建立事件 FIFO、Heartbeat、标题同步、收件箱和多份中央视图，并对每个微动作逐层传播同一事实。
3. 使用者需要向总指挥和专项窗口重复描述，或需要人工转发专项结果才能更新项目进度。
4. 为同一根因、同一 PR、同一 worktree、连续 UI 返工或普通局部任务建立多个责任窗口。
5. 只展示总指挥窗口 Token 下降，却不统计专项任务的固定提示、重复取证、等待、回执和再汇总。
6. 为维持调度体系而频繁加载长提示词、全量历史、完整日志或未变化附件。

安全边界不属于可删除的“管理开销”：精确 Base/Head、远端写入确认、未知修改保护、单写者中央状态、完成证据和可靠截点必须保留，但只能在风险和状态真正变化时更新。

## 6. 文档治理

不新建独立“规则的规则”文档。本节是文档治理的唯一主维护位置。

| 文档 | 唯一职责 |
|---|---|
| `00-第二代工作流总览.md` | 架构概览、文档导航与事实优先级摘要 |
| `01-操作者操作手册.md` | 人类入口与可复制提示词 |
| `02-总指挥核心规则.md` | 单窗口主执行内核、路由、净收益门禁与停止条件 |
| `03-专项任务卡模板.md` | 例外专项任务执行契约、任务卡与回传结构 |
| `04-状态、目标变更与交接规范.md` | 状态语义、变化与交接协议 |
| `05-模型选择与资源策略.md` | 模型、Token 与本机资源策略 |
| `06-复盘与优化规则.md` | 复盘、文档治理和流程优化 |
| `07-总指挥交接记录模板.md` | 交接记录结构与接管核验清单 |
| `08-旧版兼容与迁移规范.md` | 可选的旧版兼容与迁移边界 |
| `09-自动化授权与风险分级.md` | 风险、授权和远端写入门禁 |
| `10-自动状态索引规范.md` | 索引位置、字段、检索、回退与持久化 |

修改规则时遵守：

1. 先确定唯一主维护文档；其他文档只保留链接、入口或一句必要安全摘要。
2. 新规则优先并入现有职责，不因内容增加就创建新文件；只有出现独立读者、独立生命周期和独立加载价值时才拆分。
3. 操作手册不复制执行算法；任务与交接模板只维护各自契约，不定义新权限；索引不保存第二套项目事实。
4. 安全硬门禁允许简短重复，但详细条件仍回到主维护文档。
5. 每次版本升级前比较变更前后的行数、字节数、跨文件重复和必读文档数量；新增内容必须落入唯一职责，必要镜像要注明主来源。若复杂度增加但执行或安全收益无法证明，撤销或用等量删减抵消。
6. 操作手册面向人类，只保留 AI 无法可靠读取或不能替人决定的输入，并优先使用日常语言；内部状态、算法、ID 和可自动读取的门禁不得转嫁为人工填表。
7. `【】` 只保留操作者实际要选择或填写的规则，不能混入行动规则。开放式作答、多值账号、路径或自然语言限制确实需要帮助理解时，紧跟一个半角括号示例：`【占位符填写规则】(示例：简单、抽象、脱敏的例子)`；纯选择题不加示例。行动规则另起一句。多个同类值默认用逗号分隔；AI 可以兼容顿号或分号并自动规范化。AI 输出模板中的 `【】` 是结构，不要求机械补示例。
8. 面向使用者本人的文档和回答使用日常语言。使用者按编号提出多个问题时，至少提供相同数量的一一对应小节；可以增加必要补充，但不得通过合并问题造成漏答，也不得为了凑小节机械扩写。

### 高增长文档健康检查

任务每次读取项目进度、当前状态、拓扑、长期任务记录或其他持续增长文档时，静默检查其是否仍适合下一次阅读和交接；不要求每次都改写。文档按性质处理：

- **当前视图**：允许由唯一维护者压缩，保留当前决策所需事实和历史指针。
- **灾难恢复热快照**：与当前视图是同一份活动文档，不另建平行事实库；优先保证空白账号能定位目标、队列、断点、验证、禁止项和下一动作。写入后回读关键字段，终态过程转为冷证据指针。
- **索引**：只保留短摘要、游标和位置，不吸收长正文。
- **人工核验轮次清单**：当前轮次可按问题最小读取；关闭后转冷并默认拒绝回读。中央索引每轮只保存一个清单指针，不展开逐张附件；清单本身不因 Token 优化自动删除。
- **视觉测试包与结果卡**：测试包只保存本轮文字步骤和基线；结果卡只保存逐步骤事实、证据 ID、冲突和最小回读入口。原图留在短寿命观察任务/轮次证据清单，不复制进总指挥热状态或交接正文。
- **唯一任务记录**：保留该任务的目标、关键判断、验证、阻断和交接；终态后可生成短终态摘要，但不能抹去必要证据位置。
- **规则、会议原文、审计账本和原始证据**：不得因变长而被普通任务自动删改；规则修改走本文件规定的闭环，原始材料保持可追溯。

压缩触发和具体步骤由 `04-状态、目标变更与交接规范.md` 维护。人工核验每轮结束立即压缩并转冷；附件清理候选按 3 个关闭轮次或 30 天的软触发审查，但不得自动删除。其他文档没有过期、重复、矛盾、终态滞留或交接困难证据时，不做格式化重写；避免把节省下一次读取的收益变成每轮都要支付的维护成本。涉及移动、删除、覆盖历史文件或改变团队共享文档结构时，仍按项目规则取得单独权限。

## 7. 输出格式

最多给出 3 条改进：

```text
问题：
证据：
影响：
建议：
预期减少：
风险与验证：
```

优先顺序：先修复会影响正确性和安全性的流程，再减少 Token，最后提升自动化。

## 8. 反思边界

总指挥可以提出改进意见，但不得因为复盘自动修改当前规则、旧版文件或扩大权限。项目代码可按当前 Goal 和有效授权继续处理；工作流规则与授权边界的变更必须形成新版本并由使用者本人确认。
