# 自动状态索引规范

版本：2026-08-20.2

用途：让 AI 自动保存和检索总指挥主执行断点、轮次、例外任务、快照、授权卡、派生对象与交接 ID，减少使用者本人重复填写和双窗口转发。

本文件是索引位置、字段、检索、回退和持久化规则的唯一主维护文档。其他文档只声明何时需要状态服务，不复制本文件算法。

## 1. 存放位置

本文件只定义抽象规范，不保存任何具体项目数据。真正的索引文件统一命名为 `AI状态索引.md`，优先放在具体项目已有的个人、私有或本地管理入口/状态目录中。除非团队规则明确允许，不把个人控制面索引写进团队正式代码目录或提交到远端仓库。

总指挥按以下顺序自动定位：

1. 读取项目规则指定的管理入口或状态目录；
2. 复用该项目唯一存在且格式有效的 `AI状态索引.md`；
3. 尚无索引但管理目录唯一、可写、不会污染团队仓库且项目规则允许时，自动创建；
4. 存在多个候选、没有合适管理目录或项目规则禁止新增时，只请求使用者本人确认一次存放位置，不在仓库根目录随意新增文件。

不同项目和不同工作流实例必须使用不同索引，不得共享任务 ID、游标、授权或事件账本。

## 2. 自动记录内容

以下字段由 AI 或平台自动生成、读取、核验并写入，不要求使用者本人填写：

- 项目标识、项目根目录、远端仓库和默认分支；
- 第二代规则根目录、`00-第二代工作流总览.md` 编号注册表版本、非编号的 `总指挥轻量交接启动配置.md` 路径/版本/大小/修改时间/SHA-256，以及各规则文件的编号、规范化相对路径、大小、修改时间和 SHA-256；绝对路径只保存在项目实例索引，不写入可分发规则文档；
- 当前总指挥任务的适用规则编号、加载模式（标题级按需 / 完整 / 轻量交接 / 异常回退）、加载时间、启动配置指纹、来源规则比对结果、实际展开文件与标题、逐文件指纹和加载结果；新任务必须建立自己的加载记录，不得继承旧任务“已读”；
- Goal、轮次、状态快照、总指挥主执行阶段、例外专项任务、批量执行卡和补漏卡 ID；
- 当前唯一产品写者、主执行 worktree/文件边界，以及每个例外专项任务的创建净收益依据、隔离边界和回传位置；普通主执行不生成专项任务 ID；
- 活动母任务 ID、决策版本、已确认结论、被否决方案、未决项和交付模式；
- 主场景、目标列表、使用者本人及协作成员身份卡列表、可选范围补充/限制、默认纳入规则、队列分区、跨场景关系与冲突、规范执行记录 ID 和引用；同一对象在当前活动母任务内不得生成两条相互独立的执行记录，历史轮次记录继续保留；
- 跨模块弱关联观察项的对象标识、间接证据摘要、发现截点、推荐选择、默认排除状态、使用者本人明确选择和后续补充卡引用；不得把普通整卡确认记录为弱关联纳入确认；
- Codex 任务/窗口 ID；平台无法提供时生成本地逻辑 ID，并标记来源；
- 启动与结束时间、快照截点、增量游标和上一可靠轮次；增量游标必须能覆盖对象新增以及既有对象上的协作事件变化，不能只保存最大编号；
- Base/Head、任务分支、worktree、Issue/PR、Review、Comment 和其他派生对象；对触发 3A/3B 的最新实质协作事件，记录事件类型、操作者、时间、来源对象、关联映射指针、命中目标和正向纳入依据；
- PR 直接 Base/Head 关系和 Issue 有证据的父项、前置或阻断关系，以及本轮文本树的记录位置；不在索引中复制完整大树，也不把普通 Related 保存成依赖；
- 使用者本人 Review 绑定的 Head、当前 Head、Review 有效性、checks 与 Actions 状态；checks 为零时记录后续查询结论，不能直接标记成功；
- Issue 草案键到正式编号、实现单元和 PR 的映射，以及 Reviewer 请求、最低有效批准数和局部门禁；
- 测试、构建、CI、远端写入和交棒回执；
- 交付执行类别、估计区间及依据；首次 Push 前 CI 等价本地门禁的命令来源、绑定 Head、结果与未运行原因；实际关键路径、Push/CI波次数、CI等待期并行只读工作和可避免等待；
- 当前状态、当前行动方与动作、是否已送达及回执、完成凭证、恢复条件、后续行动方与动作，以及详细证据位置；
- 发生实质判断的对象对应的可迁移决策回执位置：待解释问题、实际选择、关键依据、未采用方案、事实截点和失效条件保留在对象/任务记录中，索引只保存对象到回执的映射，不复制正文；
- 授权卡内容、使用者本人确认原文、有效期和失效原因。
- 任务建议模型、实际可回读配置和调整原因。
- 使用者本人的必须/建议人工操作、参与类型、是否阻断当前对象、不执行影响、人工操作包位置、反馈和可复制的下一步提示词；其他成员的外部责任、协作交接、远端授权与回执单独记录。
- 按 `04-状态、目标变更与交接规范.md` 生成的高成本证据摘要 ID、来源指纹、适用对象/基线、敏感性、摘要位置和原件回读触发条件。
- 附件的必要/辅助/重复分类、必要证据缺口，以及仓库规则与通用流程差异。
- 人工核验轮次清单指针：轮次 ID、基线、问题/阶段数、证据数、访问状态、`default_read`、结案摘要、迁移表、原件回读触发条件、敏感性/存储稳定性汇总、清理候选状态和下次审查触发点。中央索引每轮只登记一条清单指针，不逐张复制附件条目。
- 通过净收益门禁时的当前视觉观察任务/逻辑 ID、绑定人工轮次、视觉测试包与结果卡位置、唯一允许写入的证据记录、权限边界、状态和失效条件。中央索引只保存一条观察任务和一张结果卡指针，不复制图片、观察任务聊天或逐图条目；观察任务不得自行写中央索引。
- 当前进度视图位置、最后核验截点、健康状态和最近一次压缩记录；压缩记录只保存移出内容的去向与校验结果，不复制正文。
- 当前进度视图同时作为灾难恢复热快照时，记录快照版本、总指挥世代、写入/回读时间、事实截点、恢复置信度、活动/暂停队列摘要、当前断点、下一动作、不可继承授权和冷证据入口；索引只存指针与短摘要，不复制快照正文。
- 便携交接快照 ID、生成时间、事实截点、正文大小、轻量启动配置路径/版本/指纹、02/04/07/09/10 来源指纹、聚合核验基线、失效条件、接收 AI/任务和返回状态增量位置。
- 空白账号灾难恢复记录：触发原因、旧任务是否可读/可写、新总指挥任务或逻辑 ID、恢复来源、事实抽查、已完成不可重复批次、执行中断批次、尚未开始批次、冲突/缺口、接管结论和新可靠截点。
- 例外专项任务恢复记录位置、创建净收益依据、隔离边界、最近断点和直接返回总指挥的状态增量；不复制专项完整日志、Diff、图片或聊天，不要求使用者转发。

索引只保存定位、摘要和校验状态。完整代码事实仍以仓库为准，Issue/PR 事实仍以平台为准，详细任务事实仍留在对应轮次或交接记录中，避免复制成第二套事实库。

## 3. 仍需人工提供的内容

只有 AI 无法可靠读取或不能替人决定的内容保留 `【】`：

- 当前使用者本人和本轮协作成员的 GitHub 账号；
- 当前一张或多张本轮协作成员身份卡；
- 本轮目标或目标功能模块；
- AI 无权访问的私聊、会议新增交办或业务背景；
- 无法从代码、平台或项目规则判断的业务取舍、专业验收和目标变更；
- 无法从团队责任记录判断的一个或多个 Issue 负责人、候选负责人和代码 PR 审阅人选择；未指定时允许形成局部门禁，不要求为继续其他阶段而猜测；
- 远端写操作、费用、生产、权限或不可逆动作所需的最终人工确认。

历史身份只用于查找候选和冲突检查，不得静默填充当前身份。历史授权只用于审计，不得自动继承到新 Goal、目标变化后的对象或新协作轮次。

## 5. 自动检索与回退

1. 先用当前项目键定位索引，再用本轮明确填写的目标、母任务和身份卡筛选候选记录；
2. 只选择结束核账完整、截点可恢复、证据位置存在且事实无冲突的最近记录；
3. 启动时用一句话回显选中的轮次、截点和依据，不要求使用者本人核对技术编号；
4. 索引缺失或过期时，先从项目、Git 和平台只读重建；
5. 无法唯一恢复时自动切换全量推进。只有身份、目标、业务含义或授权存在实质歧义时，才请求最少人工输入。

账号完全空白、旧任务不可继续或程序崩溃时，优先按以下低成本链路恢复：`项目规则入口 → 当前进度视图/灾难恢复热快照 → 当前指针 → 匹配的专项/批次记录 → 当前 Git/工作区与平台事实 → 必要冷证据`。聊天历史不是必需输入，旧任务 ID 不可获得时生成新逻辑 ID 并标记来源。恢复时先识别已完成不可重复、执行中断、尚未开始和待确认四类批次；只有热快照缺失、关键路径不存在、数量/基线/队列冲突或抽查不一致时，才扩大读取或转全量重建。

人工核验检索先锁定当前轮次。当前轮次只按阶段/问题读取清单中的最少附件；同轮总结可以选择性回读。已关闭轮次默认只读结案摘要和迁移结果，不枚举原件；只有登记的回归、冲突、摘要不足、安全/专业/合规/审计或使用者明确要求触发时，才按证据 ID 打开最少原件。Prompt Cache 命中、附件路径仍在聊天或“全量推进”都不构成回读触发条件。

当前轮次由视觉观察任务承载原图时，总指挥先读取视觉结果卡，不读取观察任务聊天或枚举清单原件。只有结果卡登记的冲突/最小回读建议，或现行原件回读触发条件命中时，才按证据 ID 读取最少图片。观察任务完成后标记 `closed`，下一大轮次建立新任务记录，不复用旧观察任务继续累积原图。

规则文件定位与判重按以下顺序执行：

1. 本轮显式提供“第二代规则文档目录”时优先验证该路径；否则从项目实例索引读取已登记根目录。只有当前对话明确提供了某个规则文件的本地路径时，才可以把其父目录作为候选并验证；不得根据文件名对整块磁盘或无边界目录做盲搜。
2. 候选目录必须至少包含 `00-第二代工作流总览.md`，并与其中 00～10 编号注册表逐项核对。场景 6A 还必须存在 `总指挥轻量交接启动配置.md`。缺文件、同编号多文件、注册表冲突或目录不可访问时，登记失败并列出具体问题。
3. 根目录缺失、旧路径失效或候选无法唯一验证时，先暂停依赖规则的项目执行，只请求使用者本人提供一次当前规则文件夹绝对路径；不要求逐个上传文档。新路径验证成功后，原子更新规则根目录、注册表版本、启动配置和逐文件指纹，并把旧路径标记为失效；不得同时保留两个活动根目录。
4. 每个新总指挥任务建立独立加载记录；旧任务记录只用于发现可能变化，不能作为本任务已读证明。普通启动和具体执行按 `02` 的“标题级按需加载映射”读取不可压缩内核、当前场景与风险章节，并记录实际标题；灾难恢复按恢复缺口读取 `02/04/09/10` 对应章节，影响范围不可靠时完整回退。场景 6A 候选完整读取轻量启动配置并比对快照中的配置及 02/04/07/09/10 来源指纹；全部一致时记录 `轻量交接`，不全文读取五份来源规则。
5. 轻量比对出现单文件指纹变化时，先根据变更标题和当前场景确定受影响范围；能够可靠限定时完整读取受影响标题并记录 `异常回退`，不能限定时完整读取该文件。配置缺失/不一致、来源清单不完整、目录迁移或无法确定影响范围时退回完整加载。旧格式快照只有在当前任务已自行完整读取旧版适用规则并于同一任务完成规则更新时，才能登记过渡加载；其他任务不得跳过。
6. 同一任务后续复用时先比较规范化路径、大小和修改时间；任一变化、元数据不可靠或安全边界较高时计算 SHA-256。只有指纹一致且本任务加载记录完整，才跳过已经完成的同级读取。
7. 同名文件、聊天中再次出现的同一附件名或 Prompt Cache 命中都不能代替指纹核验。重新上传的附件可能再次进入输入，因此本地路径可访问时优先直接读取，不要求重复上传。

索引是导航，不是事实豁免。每次执行前仍须核对当前代码、平台状态、团队规则和权限。

## 6. 更新时机与安全

- Goal、轮次、任务或批量卡创建时立即登记逻辑 ID；
- 第二代规则根目录首次确认、启动配置或规则文件新增/删除/改名/指纹变化、当前任务首次加载适用规则或发生轻量交接异常回退时，局部更新规则注册与加载记录；
- 母任务建立、结论确认/否决、未决项变化、Issue 草案转正式编号、PR 映射或 Reviewer 门禁变化时局部更新；
- Review 绑定 Head 或有效性、checks/Actions、当前行动方、送达回执、完成凭证、恢复条件、后续行动方或人工操作级别变化时局部更新；
- 对象发生实质判断、决策理由补录或失效条件命中时，局部更新对象到可迁移决策回执的映射；
- 出现持久状态变化、平台回执、任务中断、目标变化、暂停或交接时局部更新；
- 长任务、无人值守批次或多批次队列开始前，登记热快照的目标、基线、批次顺序、首个动作和禁止项；恢复意义发生变化或每个独立批次结束时，先完成原子实现/验证步骤，再在稳定截点一次性更新并回读热快照和索引指针。无持久状态变化的问答、文件保存、命令级进度和重复只读操作不更新；不得按固定分钟、消息数或工具调用高频写入，也不得同步维护任务标题、事件收件箱、Heartbeat 和多份同义视图；
- 空白账号接管开始时登记 `RECOVERY` 记录并保持只读；事实抽查通过、热快照回读完成且新总指挥世代已写入后，才把接管标记为可靠。旧授权、旧运行状态和旧任务规则加载记录不迁入新世代；
- 例外专项任务在其负责路径更新恢复记录后，直接把路径、断点和状态增量回传总指挥，由总指挥登记中央索引；专项 AI 不直接改当前总指挥、热快照或其他专项条目，使用者无需转发；
- 当前进度视图完成实质压缩、便携交接快照生成或临时 AI 返回状态增量时，登记对应记录和证据位置；
- 人工核验轮次结束、下一轮创建、问题迁移表/结案摘要/清理清单写入或清理回执变化时，局部更新轮次指针；清理未完成时不得覆盖上一可靠轮次摘要；
- 视觉隔离通过净收益门禁后，在测试包生成、观察任务建立、结果卡完成/冲突/失效或轮次关闭时，由总指挥局部更新观察任务与结果卡指针；观察任务只更新其唯一指定记录并回传，不直接改中央索引；
- 人工核验轮次关闭时将其清单设为 `closed/cold` 和 `default_read=false`，登记下一轮指针；每累计 3 个关闭轮次或距上次审查 30 天时只生成清理候选审查记录，不自动删除；
- 人工原始材料删除前后分别登记清单版本、来源指纹、文件计数、字节数、保留例外、执行回执和失败路径；索引只保存摘要与回查位置，不复制原件内容；
- 首次完成高成本材料分析或其来源指纹、适用基线、关键结论发生变化时，登记或局部更新对应 `EVIDENCE-` 记录；
- 结束核账通过后才把记录标记为可靠截点；
- 增量轮的结束核账是该轮内置收尾，不另建每日核账记录；只保存核账模式、四类差集结论、升级原因和下一可靠截点。核账未通过时保留旧可靠截点，并把本轮标记为待修复或已转全量，不能用未核账完成的时间点覆盖旧基准；
- 写入失败时保留当前任务事实并重试一次；仍失败则标记索引待修复，但不得伪称已经记录；
- 热快照写入后必须回读版本/世代、事实截点、活动目标、队列顺序、当前断点、下一动作和证据入口；回读失败时保留上一可靠索引截点，不得把新快照登记为可靠；
- 不记录密码、Token、Cookie、密钥、完整敏感日志或无关个人信息；
- 不因索引中存在旧授权而执行远端写操作；远端写入仍按本轮授权卡和当前团队规则执行。

为节省 Token，日常只读取“当前指针”、当前人工核验轮次清单、匹配的少量历史行和相关 `EVIDENCE-` 摘要指针；已关闭轮次保持 `default_read=false`。只有发生冲突、回归、审计、恢复失败、摘要不足或摘要规定的原件回读条件时才展开详细记录或原始材料。
