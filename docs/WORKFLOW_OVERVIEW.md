# 工作流概览

## 目标

本工作流用于在上下文受限、多个任务并行且需要人工控制风险的环境中，把项目目标拆成可审计的执行单元，并确保任何公开或不可逆动作都有明确门禁。

## 角色与职责

### 项目总指挥

- 维护目标、范围、事实基线、优先级和验收标准。
- 生成已脱敏的规则增量事件包，并路由给相关专项任务。
- 汇总结果、处理冲突、裁决待确认事项。
- 请求并记录人工对高影响动作的最终授权。

### 专项任务

- 只处理事件包规定的范围，不主动获取无关上下文。
- 基于仓库内证据执行最小改动与适当验证。
- 以稳定事件包回传结果，不直接向其他专项任务广播。
- 遇到越界、泄密风险或授权缺失时立即停止。

### 人工维护者

- 决定目标、许可证、公开策略和风险接受程度。
- 审批远端写入、发布、权限、费用与不可逆动作。
- 对无法由自动检查证明的差异和隐私边界进行最终核对。

## 基本流程

1. **建立事实基线**：总指挥确认仓库状态、任务边界和验收标准。
2. **生成事件**：把必要规则压缩为脱敏、结构化的增量事件。
3. **路由任务**：事件只发送给确有需要的专项任务。
4. **局部执行**：专项任务在授权范围内修改、测试并进行对抗式审查。
5. **稳定回传**：专项任务回传事件 ID、变更、验证、隐私检查、Commit SHA 与待裁决事项。
6. **人工门禁**：高影响或远端动作必须等待针对具体对象、动作和内容的明确授权。
7. **安全交付**：核对差异、状态和检查结果后，执行获批动作并记录结果。

## 不可抢占的前台任务与 FIFO

每个窗口维护一个前台任务和一个先进先出（FIFO）队列。FIFO 表示先到达的待处理事件先执行；到达顺序以窗口实际观察到的接收顺序为准。

执行协议如下：

1. 窗口空闲时，队首事件成为唯一前台任务。
2. 前台任务执行期间，新事件、委派或独立回调只入队，不改变当前执行目标。
3. 完成实现与验证后，必须向用户发送一份独立、完整的最终反馈；该反馈发送成功才构成前台任务的完成边界。
4. 稳定事件包、工具回执、Commentary、任务记录和消息卡可以作为过程证据，但不能替代最终反馈。
5. 前台任务结束后，窗口才能按 FIFO 顺序取出下一事件。

不可抢占规则只有两类例外：用户明确取消或替换当前任务；继续执行会造成安全风险或使依据失效。例外发生时，应记录停止原因和最后一个可验证断点。

若发生插队、断点丢失或漏发最终反馈，则插队之后的完成声明无效。恢复时应把新事件退回原队列，从原任务最后一个可验证断点继续，补齐验证与用户最终反馈后，再恢复正常出队。

## 事件状态

- `proposed`：事件已起草，尚未确认范围。
- `accepted`：范围和验收标准已确认，可以执行。
- `in_progress`：正在执行本地、可回滚的工作。
- `blocked`：存在授权、输入或安全阻断。
- `verified`：改动已完成并通过约定验证。
- `delivered`：获批交付动作已完成。
- `rejected`：事件被明确拒绝，不再执行。

状态变化必须由可核对的事实触发，不能仅凭预计结果更新。

## 人工门禁

以下动作至少需要一次最终明确确认：

- 创建远端资源或改变共享平台状态；
- 发布、部署、合并或修改分支保护；
- 涉及权限、凭据、费用、生产数据或不可逆变化；
- 公共接口破坏性变更、数据迁移或重大架构决策。

确认请求应说明目标对象、精确动作、内容范围、已验证结果、风险和回滚方式。旧授权不能自动扩展到新对象或新动作。

## 最小回传字段

稳定回传至少包含：

- 事件 ID；
- 修改摘要与原因；
- 验证命令、结果和未验证项；
- 隐私与 Secret 检查结果；
- 本地 Commit SHA（如已提交）；
- 待裁决事项；
- 远端授权请求（如需要）。

事件格式见 [规则变更事件模板](../templates/RULE_CHANGE_EVENT.md)。
