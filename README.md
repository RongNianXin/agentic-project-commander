# Codex Workflows

Codex Workflows 是一套面向 Codex Desktop 的工作模式、故障检查方法、技巧性提示词和本地辅助工具。仓库内容以可下载、可审查和不携带私人资料为基本边界。

## 内容分类

1. [第二代总指挥的工作模式](第二代总指挥的工作模式/)：薄总指挥、Goal、专项任务、状态交接、授权门禁和复盘规则。
2. [故障检查](故障检查/)：已复现并脱敏的 Codex 故障排查方法。
3. [其他 Codex 技巧性提示词](其他%20Codex%20技巧性提示词/)：可直接复制或按需修改的通用提示词。
4. [实用小工具](实用小工具/)：辅助查看和维护 Codex 本地工作状态的工具。

根目录中的 `AGENTS.md`、`.gitignore`、`CHANGELOG.md` 和 `LICENSE` 分别维护 AI 工作边界、Git 忽略规则、版本记录和许可证。

## 第二代工作模式快速开始

1. 下载或克隆本仓库。
2. 阅读 [00-第二代工作流总览.md](第二代总指挥的工作模式/00-第二代工作流总览.md)。
3. 按 [01-操作者操作手册.md](第二代总指挥的工作模式/01-操作者操作手册.md) 登记本地规则目录并选择使用场景。
4. 需要轻量交接时，使用 [总指挥轻量交接启动配置.md](第二代总指挥的工作模式/总指挥轻量交接启动配置.md)。

规则仓库与真正要开发的目标项目应分开。只有维护这套规则本身时，才把本仓库作为 Codex 的目标项目。

## 实用工具

[查看当前任务本地对话的文件大小](实用小工具/查看当前任务本地对话的文件大小/)提供只读 PowerShell 脚本和脱敏使用说明，可显示本地会话文件大小、自动压缩次数、最近输入占窗口比例和交接建议。

工具中的容量分级、压缩次数和 85% 观察线属于本地经验规则，不是 OpenAI 官方限制。

## 私有资料与同步边界

- `/其他资料/` 只保存在本地，由 `.gitignore` 阻止 Git 跟踪。
- 根目录 `AGENTS.md` 要求 AI 未经当前任务明确授权，不读取、搜索、修改或上传该目录。
- `.gitignore` 不能替代访问权限；高度敏感资料应放在仓库和 Codex 工作区之外。
- 已经进入 Git 历史的文件不能靠新增忽略规则消除，需要单独清理历史并轮换已泄露的凭据。
- 提交前应核对 `git status` 和 `git diff --cached`，并只暂存明确路径。
